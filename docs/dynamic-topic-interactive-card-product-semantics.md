# 词条主题动态交互卡产品语义声明

## 1. 产品目标

DUDesign 的该产品模式不是传统意义上的百科产品，也不以生成百科文章、百科详情页或百科站点页面为目标。

产品目标是：

> 以一个词条、实体、概念、人物、作品、地点或事件作为主题入口，生成一张具有明确主题表达、视觉叙事和本地交互能力的动态卡片。

词条用于确定主题、事实边界和内容语境；动态交互卡片才是最终产品形态。

## 2. 不是什么

- 不是百科文章的缩略版。
- 不是标题、摘要、信息框、目录、正文段落的传统百科页面复刻。
- 不追求对词条知识的穷尽式覆盖。
- 不要求按百科章节顺序组织全部事实。
- 不模仿任何公开百科、搜索引擎或知识产品的界面与视觉资产。

## 3. 应该是什么

- 单屏或固定画布内可直接体验的主题卡片。
- 围绕用户当前需求选择一个主要交互命题，例如成员探索、关系发现、阶段演进、对比辨析、路线导览或渐进披露。
- 通过 tab、分页、局部切换、展开、弹层、关系节点或时间节点形成真实本地交互。
- 允许主题化视觉语言、信息层级和叙事节奏，不受传统百科页面结构限制。
- 内容可以有选择地呈现，只要覆盖用户目标并保持事实边界清晰。

## 4. 事实与设计的关系

- 事实可靠性是底线约束，不是页面形态。
- 分类用于选择合适的交互范式和内容模块，不用于强制生成百科目录。
- democase 用于学习布局、交互节奏和视觉组织，不用于复制具体事实、文案或品牌外观。
- 资料不足时应降低内容密度、隐藏不可靠模块或显示不确定性，不应为了“百科完整”而补造事实。

## 5. 质量优先级

1. 主题和用户意图是否清晰。
2. 主要交互是否有价值且真实可操作。
3. 固定画布内的视觉层级、节奏和信息密度是否合理。
4. 所选内容是否服务当前交互命题。
5. 事实是否中立、可追溯或明确标注不确定性。
6. 响应式、iframe、安全和静态导出是否可靠。

不以正文长度、章节数量、事实总量或百科式覆盖率作为主要质量指标。

## 6. 兼容策略

- 第一阶段保留内部 `dynamic_encyclopedia_card`、`dtp_dynamic_encyclopedia_*` 等稳定 ID，避免破坏旧 job/session、数据库和 Runtime Contract。
- 用户端展示、产品文档和生成 prompt 使用“词条主题动态交互卡”语义。
- 后续如需迁移到 `dynamic_topic_card`，必须提供 alias、历史快照读取和 contract version 兼容方案。
